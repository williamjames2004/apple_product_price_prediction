Project Overview

About This Project

This project demonstrates a complete machine learning workflow: loading historical product records, preparing input features, training a regression model, evaluating its predictions and serving the trained model through a Flask web application.

Dataset Analysis

Uses product records containing platform, category, condition, pricing, discounts, ratings and reviews.

Decision Tree

Learns feature-based decision rules and predicts a continuous numerical price.

Model Evaluation

Reports Mean Absolute Error and, when calculable, the coefficient of determination R².

Interactive Website

Accepts new product information and displays an estimated price through a browser form.

Project Objectives

  • Understand how product attributes relate to current prices.
  • Apply preprocessing to categorical and numerical features.
  • Train a Decision Tree Regressor using historical examples.
  • Measure prediction errors on a held-out test dataset.
  • Demonstrate a trained machine learning model using Flask.
  • Understand the limitations of predictions made from historical data.

Machine Learning Theory

Decision Tree Regressor Explained

A Decision Tree Regressor is a supervised machine learning algorithm that predicts numerical values by learning a sequence of feature-based rules from training examples.

1. What is a Decision Tree?

A decision tree organizes learned rules into a tree-like structure. Each internal node checks a condition on a feature, each branch represents the result of that condition, and each leaf provides a prediction.

For example, a simplified tree might first split products by launch price, then split a group by rating or discount. After following the relevant branches, the model produces a predicted current price.

Product Features
    ↓
Check a learned feature condition
    ↓
Follow the matching branch
    ↓
Continue until a leaf is reached
    ↓
Predicted Current Price (INR)

This is an illustrative flow, not the exact set of rules learned by your trained model.

2. How Does Regression Work?

Classification predicts a category, such as spam or not spam. Regression predicts a numerical quantity, such as price, salary or house value. This project uses regression because the target Current_Price_INR is a continuous numerical value.

During training, the algorithm searches for splits that divide the records into groups with lower variation in their target prices. At a leaf, the usual Decision Tree Regressor prediction is the mean target value of the training samples that reach that leaf.

3. How Does the Tree Choose a Split?

The tree evaluates candidate feature thresholds and compares the squared errors within the resulting groups. A useful split creates groups whose target prices are more consistent.

Mean Squared Error = (1 / n) × Σ (yᵢ − ȳ)²

Here, yᵢ is an actual target price, ȳ is the mean target price in the group, and n is the number of records in that group. The tree chooses splits that reduce the impurity measure according to its splitting criterion.

4. Data Preprocessing

Step 1 — Select relevant features

The application uses nine input columns and excludes the target column from the inputs.

Step 2 — Handle missing values

The model pipeline fills missing categorical values using the most frequent category and missing numerical values using the median of the training data.

Step 3 — Encode categorical features

OneHotEncoder converts text categories into numeric indicator columns. For example, different platform values become separate encoded features. Unseen categories are ignored instead of causing an encoding error.

Step 4 — Keep numerical features numeric

Launch price, discount percentage, rating and review count remain numerical. Decision trees do not require numerical feature standardization.

Step 5 — Train the regressor

The preprocessor and Decision Tree Regressor are combined in one pipeline, ensuring that the same transformations are applied during training and prediction.

5. Why Is max_depth Set to 8?

Your model uses max_depth=8. This limits the maximum depth of the tree and can reduce the risk of learning overly specific rules from the training data.

A tree that is too deep may overfit, memorizing patterns that do not generalize well. A tree that is too shallow may underfit and miss useful relationships. The best depth depends on the dataset and should ideally be selected using validation or cross-validation.

Advantages

  • Easy to explain compared with many complex models.
  • Can learn nonlinear relationships.
  • Can represent interactions between features.
  • Does not require feature scaling.
  • Works with encoded categorical and numerical data.

Limitations

  • Can overfit if the tree is too complex.
  • Predictions can change when training data changes.
  • Leaf predictions may be poor for unseen price ranges.
  • Historical patterns may not represent today's market.
  • Data errors and biased samples affect reliability.

Understanding the Metrics

Mean Absolute Error (MAE)

MAE is the average absolute difference between actual prices and predicted prices. If MAE is ₹500, the model's predictions differ from actual test prices by ₹500 on average in absolute terms. This is an example for explanation, not a measured result from your dataset.

MAE = (1 / n) × Σ |Actual Price − Predicted Price|
R² Score

R² compares the model against a baseline that predicts the mean target value. A value near 1 indicates strong fit on the evaluated data; a value near 0 means performance is similar to that baseline; a negative value means the model performed worse than the baseline. R² can be undefined or unreliable for very small test sets.

No accuracy percentage is shown because this is a regression problem. MAE and R² are more appropriate measures than classification accuracy. Metrics depend on your actual data.csv.

Practice and Viva Preparation

Sample Questions and Answers

Use these questions to prepare for a project demonstration, viva voce or machine learning interview.

Q1. What is the main objective of your project?

To estimate a product's current price in INR using product attributes and a supervised machine learning regression model.

Q2. Why did you choose a Decision Tree Regressor?

It can learn nonlinear relationships, model feature interactions and provide an understandable rule-based structure for numerical prediction.

Q3. What is the difference between classification and regression?

Classification predicts discrete classes, while regression predicts numerical quantities such as a product's price.

Q4. What is the target variable?

Current_Price_INR is the target variable.

Q5. Why use One-Hot Encoding?

It converts categorical text values into numerical indicator features that the model can process.

Q6. Why use a pipeline?

A pipeline keeps preprocessing and model prediction together, helping ensure that the same transformations are applied to training and new inputs.

Q7. What is the purpose of train_test_split?

It separates records into training and testing subsets so performance can be measured on records not used to fit the evaluation model.

Q8. Why is random_state set to 42?

It makes the train-test split and tree randomness reproducible for the same data and software setup. The number 42 has no special mathematical advantage here.

Q9. What does max_depth=8 control?

It limits how deep the decision tree can grow, helping control model complexity.

Q10. What is the difference between MAE and R²?

MAE measures the average absolute prediction error in the target's units. R² compares the model's fit with a mean-prediction baseline.

Q11. Why should preprocessing be fitted only on training data?

To avoid information from the test set influencing the learned preprocessing values and making evaluation misleading.

Q12. Can the model predict prices for completely new products?

It can produce a prediction from the provided attributes, but reliability may be poor when the new product differs substantially from the training data.

Q13. What are the limitations of your project?

Prediction quality depends on dataset size, quality, representativeness, historical relevance and the model's ability to generalize.

Q14. How could the project be improved?

Compare alternative regressors, tune hyperparameters, use cross-validation, gather more recent data and evaluate the model on later time periods.

Q15. Why is the saved model useful?

It stores the fitted preprocessing pipeline and regressor, allowing the application to make predictions without retraining for every form submission.
